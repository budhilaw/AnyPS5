# Project technical debt

### Build

- Building on Windows requires a specific version of mingw - MinGW-w64 GCC 15.2.0 (`winlibs-gcc15`, `x86_64-ucrt-posix-seh`)
- Even compiled prx libraries on Windows require nearby (static linking of these dependencies causes conflicts):
  - libgcc_s_seh-1.dll
  - libstdc++-6.dll
  - libwinpthread-1.dll

### macOS host

- [nid_patcher](../core/libs/nid/src/BinaryPatcherFactory.cpp) understands ELF and PE only. On macOS the libraries keep their source export names and the link step adds the NID names as linker aliases ([link-with-nid-aliases.sh](../core/libs/nid/darwin/link-with-nid-aliases.sh)); every global symbol gets an alias, including C++ internals, which is harmless but noisy.
- The guest x86-64 ABI runtime is compiled with Apple Clang for x86-64 (`ANYPS5_GUEST_ABI`); the exception runtime targets libc++abi instead of libstdc++ ([CxxAbi.hpp](../core/libs/prx/libc/include/specifics/itanium/CxxAbi.hpp)). Native arm64 builds get a host-only libc for the tests.
- Guest thread storage: the relinker rewrites `mov %fs:0` into a `%gs` thread-specific-data slot ([MachOTlsRewriter](../core/relinker/elfpatcher/src/darwin/MachOTlsRewriter.cpp)); only that access form is rewritten, so other `%fs` addressing forms would need more patterns.
- The relinked executable is non-PIE because dyld slides images in 4 KiB steps while the guest assumes 16 KiB pages; guest modules (dylibs) are still slid, so [`sceKernelMprotect`](../core/libs/prx/libkernel/DirectMemory/DirectMemory.cpp) rounds to host pages on Apple.
- The guest's `main` runs on a secondary thread ([GuestMain.cpp](../core/libs/prx/libc/src/specifics/darwin/GuestMain.cpp)) while the process main thread runs a CFRunLoop; every SDL window or event call goes through [MainThread::Run](../core/libs/prx/libSceVideoOut/src/MainThread.mm). A host program that runs guest code on its main thread executes them in place.
- Metal is reached through MoltenVK, not a native backend. A native Metal backend would duplicate the whole [Vulkan execution layer](../core/libs/prx/libSceAgcDriver/Execution) and is not planned while MoltenVK covers the driver's requirements (`VK_KHR_buffer_device_address`, `VK_KHR_shader_float_controls`, `VK_KHR_8bit_storage`).
- Rosetta 2 translation is the only way to run the x86-64 guest on Apple Silicon; there is no arm64 recompilation.
- `sceKernelRaiseException` (signal delivery into another guest thread) and the guest exception handlers registered with `sceKernelInstallExceptionHandler` are recorded but never invoked with a synthesized machine context.

### Windows host

- The SysV red zone is not preserved: Windows writes the exception record below `rsp` when it dispatches a guest page fault, so a guest leaf function that faults on tracked memory loses up to 128 bytes of its locals ([UnchartedStatus](UnchartedStatus.md)). Guest code is not patched to lower `rsp` around such accesses yet.
- Guest memory tracking and transient remaps rely on vectored exception handlers ([MemoryTrackingWindows](../core/libs/prx/libc/src/MemoryTrackingWindows.cpp), [MemoryBackingWindows](../core/libs/prx/libc/src/MemoryBackingWindows.cpp)); a fault takes the global tracking lock, so a guest thread can wait behind a long driver operation.
- Timed waits bypass winpthreads' 15.6 ms rounding with high-resolution waitable timers ([PreciseWait](../core/libs/prx/libc/include/PreciseWait.hpp)).

### PS5 title coverage (Unity / il2cpp)

- APR file reads ([libkernel Apr](../core/libs/prx/libkernel/Apr/src/Apr.cpp), [libSceAmpr](../core/libs/prx/libSceAmpr/Export.cpp)) execute synchronously at submission; only the read-file command is implemented (no gather/scatter, kernel-event or AMM commands).
- The driver worker steps every queue one packet per round ([Driver](../core/libs/prx/libSceAgcDriver/Execution/src/Driver.cpp)), so a `WAIT_REG_MEM` blocks only its own queue while the others (and the title) run, as on the console's graphics and compute pipes; an unsatisfied wait times out after 30 seconds. Label writes (`RELEASE_MEM`, label-sized `WRITE_DATA`/`COPY_DATA`/`DMA_DATA`) behind pending GPU work are deferred to the completion of the draw batch recorded before them, and waits see the deferred value meanwhile; `RELEASE_MEM` interrupts wake every event registered with `sceAgcDriverAddEqEvent`. Compute dispatches join the draw batches. Cache events, `PFP_SYNC_ME` and `ACQUIRE_MEM` are queue barriers; host-executed memory transfers wait only for pending GPU work that writes their ranges. A submission counts as completed once its packets are recorded; `sceAgcDriverWaitIdle`-style waits go through a suspend-point boundary that drains the device.
- Guest buffers bound by shaders live in persistent GPU mirrors ([GuestBufferCache](../core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferCache.cpp)) validated by 64 KiB chunk watches over guest memory (a CPU write ages the chunk); chunks that share pages with a render target or are unmapped copy on every use, read-only mappings count as immutable until a guest protection change. Only buffers the shader stores to are written back after the GPU work completes. Textures use the same change stamps to skip the byte comparison of their guest surface ([TextureCache](../core/libs/prx/libSceAgcDriver/Graphics/src/TextureCache.cpp), 4 GiB budget, `ANYPS5_TEXTURE_CACHE_MB`).
- Guest buffer descriptors bind from a 256-byte aligned base and the recompiler bakes the address residue into the shader data memory-offset bytes ([DescriptorBindingBuilder](../core/shader/recompiler/Optimization/src/DescriptorBindingBuilder.cpp)); descriptors with type field 3 are accepted as buffers.
- Render targets other than 32-bit-per-pixel (16-bit float, packed 10:10:10:2 rendered as 16 bpp), mip levels and array slices are GPU-only: they are never written back to guest memory, so the CPU cannot read them. Shader stores into detiled textures stay on the device too.
- Depth and stencil buffers sampled as textures (the `64KB_Z_X` swizzle) are read through a depth- or stencil-aspect view of the resident depth image in the read-only depth layout, and the next depth pass returns the image to the attachment layout ([TextureCache](../core/libs/prx/libSceAgcDriver/Graphics/src/TextureCache.cpp)). A draw that samples the depth buffer it renders to, arrays of resident slices, depth formats the device cannot filter linearly, a fifth distinct view of one depth image and `ANYPS5_DEPTH_COPY` still copy the depth or stencil plane through a buffer into a single-channel image each time a draw writes the depth image ([DepthTexture](../core/libs/prx/libSceAgcDriver/Graphics/src/DepthTexture.cpp)); views that change the texel size, extent or mip range of a resident depth image are rejected.
- 3D textures follow the GFX10 addrlib volume rules ([TextureTiling](../core/libs/prx/libSceAgcDriver/Graphics/src/TextureTiling.cpp)): the standard `4KB_S` and `64KB_S` swizzles tile volumes in thick blocks (each slab of block depth holds the whole mip chain with its own mip tail) and are detiled by one dispatch per mip, while `64KB_Z_X` and `64KB_R_X` are thin and detile slice by slice. The thick display swizzle `64KB_D_X` is not decoded. Storage-image write ranges ([Driver](../core/libs/prx/libSceAgcDriver/Execution/src/Driver.cpp)) still size thick volumes as one thin slice per depth level: that is more than the volume for deep ones such as the 32x32x32 LUT (2 MB for 128 KB), which only costs waits, and less for shallow, wide ones (512 KB of a 128x128x8 RGBA8 volume's 1 MB), which is safe only while shader stores into 3D textures stay on the device.
- Texture and sampler descriptor fields that the driver does not emulate are ignored, each logged once ([GuestTextureResource](../core/libs/prx/libSceAgcDriver/Graphics/src/GuestTextureResource.cpp), [GuestSamplerResource](../core/libs/prx/libSceAgcDriver/Graphics/src/GuestSamplerResource.cpp)):
  - Textures: the mip statistics counters that feed the title's texture streamer (`MIP_STATS_CNT_EN`/`MIP_STATS_CNT_ID`; they are never updated, so a streamer that relies on them may keep textures at their low mips), the partially resident default color, `MIN_LOD_WARN`, the DCC and metadata fields (guest surfaces are always read uncompressed because the driver never writes compressed data) and `BC_SWIZZLE` (border colors keep their channel order).
  - Samplers: `PERF_MIP`/`PERF_Z`, the anisotropy threshold, bias and override, the secondary LOD bias, `MIP_POINT_PRECLAMP`, PRT blend-zero and `DISABLE_CUBE_WRAP` (Vulkan cube sampling is always seamless). A border color table entry samples as transparent black.
  - `MIN_LOD` is honoured through `VK_EXT_image_view_min_lod`, clamped to the view's mip range; a device without the extension samples the full mip range.
- A texture or sampler descriptor that still cannot be used binds a null texture of the binding's shape and numeric class (RGBA8 unorm for float bindings, R32 uint or sint for integer ones, read from the class the recompiler encodes in the binding number; the sampled view of an integer one repeats its red channel, so every channel reads zero like a zero descriptor on the console) or a linear, clamp-to-edge sampler that keeps the descriptor's depth comparison, and its words are logged once per distinct error ([ShaderResources](../core/libs/prx/libSceAgcDriver/Graphics/src/ShaderResources.cpp)). This covers unsupported tile modes, types and formats, corner sampling, array pitch, MSAA, invalid mip ranges, image shapes the shader cannot view the texture as, storage images whose format cannot be stored to, unnormalized coordinates, reduction filters, forced sRGB, skipped degamma and coordinate truncation. Storage bindings, including zero descriptors, bind a separate null texture per shape and class that sampled bindings never read, so sampled null textures stay zero; the console drops stores through a null descriptor, but here a load through such a storage binding may return what an earlier store left in it, and a load through an integer one reads one in alpha because storage views keep the identity swizzle. A failure inside the texture cache, after it may have recorded GPU work, still stops the driver.
- `CB_COLOR_CONTROL` mode 0 (color buffer disabled) is treated as a depth-only draw; blend modes other than normal rendering with the copy ROP are rejected.
- Stencil operations write the console's values through Vulkan's single reference and write mask per face ([State](../core/libs/prx/libSceAgcDriver/Graphics/src/State.cpp)): `REPLACE_OP` (`STENCILOPVAL`), `ONES` and `REPLACE_TEST` move their value into the reference on the written bits the stencil test does not compare (every bit under `ALWAYS` and `NEVER`), and `AND`, `OR`, `XOR` and `XNOR` narrow the write mask to the bits they change when they are the only kind of writing operation of the face. The remaining cases are approximated and logged once per operation: replace values that disagree with each other or with the compared reference bits keep the reference, `NAND` and `NOR` run as `INVERT`, and `ADD`/`SUB` with a `STENCILOPVAL` above one step by one (zero keeps the stencil). An `AND`, `OR`, `XOR` or `XNOR` next to a different writing operation in the same face is rejected.
- With `ANYPS5_SKIP_FAILED_PROGRAMS` set, a draw whose register state the driver cannot translate (for example `DB_RENDER_CONTROL` depth or stencil copies, unsupported blend factors or color formats) is skipped and its error is logged once per distinct message ([Driver](../core/libs/prx/libSceAgcDriver/Execution/src/Driver.cpp)); without the switch the driver stops.
- Dual-source blending (`DB_SHADER_CONTROL.DUAL_EXPORT_ENABLE`) maps MRT0/MRT1 to blend sources 0/1 of color target 0; it needs the device's `dualSrcBlend` feature (MoltenVK has it). Cube maps get their own image binding slot per sampled class, so a shader may sample cubes and 2D arrays through the same instruction class.
- Compute pipelines are cached per SPIR-V and descriptor layout ([VulkanDevice](../core/libs/prx/libSceAgcDriver/Execution/src/VulkanDevice.cpp)); Unity's loading phase still compiles dozens of distinct compute programs at up to a second each on MoltenVK (the Metal compile), which the persisted pipeline cache does not avoid.
- Reader-writer locks ([Rwlock](../core/libs/prx/libkernel/Pthread/src/Rwlock.cpp)) follow libthr: recursive read locks are granted while a writer waits, writers are preferred otherwise. Timed lock variants are not implemented.
- `INDIRECT_BUFFER` (`sceAgcDcbJump`) is flattened when the stream is copied at submission, so a jump target rewritten by the title after submission is not seen.
- Indirect draws read their arguments at execution time; the CP's user-SGPR patching of vertex/instance offsets is emulated through the draw parameters.
- The shader recompiler rejects compute shaders whose buffer descriptors are derived from `WorkgroupId` (seen in Unity's first compute dispatch); the origin of that pattern is not analysed yet.
- `sceAudioOut2` mixes the title's output ports to a stereo 48 kHz SDL device; `libSceAjm` decodes ATRAC9 with LibAtrac9 (batches run synchronously at start; other codecs output silence). `libSceAvPlayer` and the IME/message dialogs remain stubs; HTTP/SSL/NP networking is implemented as an offline network (every connection fails with a network-down error and the title continues without PSN).

### Functional

- There's no way to specify keyboard and mouse input mapping when using a gamepad. The [default mapping](../core/libs/prx/libScePad/include/InputMapping.hpp) is always used.
- [Shader recompilation](../core/shader/recompiler/Recompiler.cpp) currently occurs right before it was transferred to Vulkan with caching, but should be moved to the [relinker](../core/relinker/main.cpp) stage. For this purpose, [shader/recompiler](../core/shader/recompiler) was written completely independently from [libs/prx](../core/libs/prx).
- The executable file that [relinker](../core/relinker/elfpatcher/src/windows/WindowsPeWriter.cpp) generates opens the console when launched, which is inconvenient for playability.
- [Relinker](../core/relinker/elfpatcher/src) doesn't add an icon to the generated executable. This should be done without adding dependencies (only standard).
- The game can expect its modified prx from the `sce_module`/`sce_modules` folder - this support is not implemented.
